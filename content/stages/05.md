<!-- block: brief -->
Stage 04 treated main memory as "the slow thing behind the cache". This hour
opens it.

Two questions decide everything here: **what is one bit physically made of**,
and **what happens when it is wrong?** The second is not hypothetical — memory
errors are routine at scale, and a machine that cannot detect one silently
computes the wrong answer.

<!-- block: prose -->
## A memory cell, in the abstract

Whatever the technology, a cell does three things: it holds one of two states,
it can be written, and it can be read. Everything below is an implementation of
that contract — which is Stage 01's distinction again, one level down.

Two implementations dominate, and they differ in a way you can feel in the
price list.

<!-- block: prose -->
## DRAM: a charged capacitor

<!-- block: quote source="ch-05.md 5.1" -->
dynamic RAM (DRAM) is made with cells that store data as charge on capacitors. The presence or absence of charge in a capacitor is interpreted as a binary 1 or 0. Because capacitors have a natural tendency to discharge, dynamic RAMs require periodic charge refreshing to maintain data storage.

<!-- block: prose -->
Read that last sentence again, because it is the whole character of DRAM.
**A DRAM cell leaks.** Left alone, it forgets — in milliseconds. So the memory
controller must walk the entire array thousands of times per second, reading
each row and writing it back, purely to stop it decaying.

That refresh is not free. During it, rows are unavailable, and the "dynamic" in
the name is a permanent tax on every access.

What you buy for it: **one transistor and one capacitor per bit.** That is the
smallest, cheapest cell anyone has built, which is why every gigabyte in your
machine is DRAM.

<!-- block: prose -->
## SRAM: a flip-flop

<!-- block: quote source="ch-05.md 5.1" -->
In contrast, a static RAM (SRAM) is a digital device that uses the same logic elements used in the processor. In a SRAM, binary values are stored using traditional flip-flop logic-gate configurations

<!-- block: quote source="ch-05.md 5.1" -->
A static RAM will hold its data as long as power is supplied to it.

<!-- block: prose -->
No capacitor, no leak, no refresh. Faster, and available every cycle.

The price is **six transistors per bit** instead of two components — several
times the area, several times the cost, and more power at rest.

<!-- block: callout -->
**This is Stage 04's hierarchy, explained.**

| | DRAM | SRAM |
|---|---|---|
| Per bit | 1 transistor + 1 capacitor | ~6 transistors |
| Refresh | Required | None |
| Speed | Slower | Faster |
| Cost/bit | Low | High |
| Used for | Main memory | Cache, registers |

Cache is not "faster memory" by magic. **It is a different cell**, and you can
only afford a little of it. The memory hierarchy is this table, arranged.

<!-- block: prose -->
## ROM, and the family that grew out of it

Some things must survive a power cut — boot code, firmware, a device's identity.
The read-only family answers that, and its history is a slow slide from *never
writable* to *writable, carefully*:

- **ROM** — written at manufacture. Wrong once, wrong forever.
- **PROM** — written once by the customer, electrically.
- **EPROM** — erasable, by ultraviolet light, all at once.
- **EEPROM** — erasable electrically, byte at a time, in place.
- **Flash** — erasable electrically in *blocks*. The compromise that won: faster
  and denser than EEPROM, and it is what your SSD and your phone are made of.

Note the pattern — each step trades a little permanence for a lot of
convenience, and **flash sits at the point where the trade paid off commercially.**

<!-- block: prose -->
## When a bit is wrong

Memory fails in two ways, and the distinction matters because the responses
differ.

- A **hard failure** is permanent physical damage. The cell is stuck. Only
  replacement fixes it.
- A **soft error** is a random, non-destructive event — a stray particle, a
  power fluctuation — that flips a bit. **The cell is fine.** Write it again and
  it works.

Soft errors are the common case and the dangerous one, because nothing looks
broken. The machine simply computed something false.

<!-- block: prose -->
## Hamming's answer

The trick is to store extra bits that constrain the data bits, so an error
breaks the constraint in a way that identifies *which* bit broke.

<!-- block: quote source="ch-05.md 5.4" -->
Hamming code devised by Richard Hamming at Bell Laboratories.

<!-- block: prose -->
The textbook's own illustration is three overlapping circles for four data bits:

<!-- block: code -->
Four data bits in the inner compartments,
one parity bit per circle in the outer ones.

Each parity bit makes its own circle's total even.

        ┌───────────┐
        │  P1   ┌───┼───────┐
        │   ┌───┼─┐ │       │
        │   │ D1│D2│ │  P2  │
        │   │   └─┼─┼───┐   │
        └───┼─────┘ │   │   │
            │ D3│D4 │   │   │
            └───┼───┼───┘   │
                │ P3│       │
                └───┴───────┘

Flip one data bit and it breaks the parity of every circle
it belongs to. The SET of broken circles names the bit.

<!-- block: prose -->
This is **SEC-DED** — single error correcting, double error detecting. One
flipped bit is found *and repaired* with no software involvement. Two are
detected but not repaired, which is the honest answer: the machine reports the
fault instead of pretending.

<!-- block: callout -->
**Why this is on your syllabus and not just in a footnote.** At scale, soft
errors are not rare — a large server's memory sees them regularly. ECC is why a
bank's ledger and a hospital's records are not quietly wrong.

It costs bits: 8 check bits for 64 data bits is a 12.5% overhead. That is the
price of knowing.

<!-- block: prose -->
## Making DRAM keep up

DRAM latency has improved far more slowly than processor speed — the gap Stage
02 called out. The advances have therefore attacked **throughput** rather than
latency:

- **SDRAM** — synchronous. The memory takes a clock and pipelines requests,
  instead of handshaking asynchronously.
- **DDR** — double data rate. Transfers on *both* clock edges. DDR2, DDR3, DDR4
  each raise the internal prefetch, which is why the numbers climb while the
  underlying cell stays roughly as slow.
- **Cache DRAM** — a small SRAM cache on the DRAM chip itself.

<!-- block: callout -->
**Notice the pattern.** None of these makes a DRAM cell faster. They pipeline,
prefetch, and overlap — they hide latency rather than removing it. That is the
same move as caching, one level down, and it is what "improvements in chip
organization" meant in Stage 02.
