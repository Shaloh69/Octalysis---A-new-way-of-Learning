Stage 01 named four components. Stage 02 gave you a way to measure whether an
arrangement of them is any good.

This chapter is where they start **moving**. Everything a computer does is one
loop repeated a few billion times a second, and by the end of this hour you
should be able to walk it step by step with the register values in front of you.

<!-- block: prose -->
## The instruction cycle is the whole machine

Two steps. That is the entire idea:

<!-- block: code -->
   ┌─────────────┐         ┌──────────────┐
   │    FETCH    │ ──────▶ │   EXECUTE    │
   │  next instr │         │  this instr  │
   └─────────────┘ ◀────── └──────────────┘

<!-- block: prose -->
**Fetch.** The **program counter (PC)** holds the address of the next
instruction. The processor reads that address from memory into the
**instruction register (IR)**, and increments the PC.

**Execute.** The processor decodes what is in the IR and does it — an
arithmetic operation, a memory access, a jump.

Then it does it again. Forever, until it is switched off.

Every remaining chapter of this course is a refinement of one of those two
boxes. Caching makes fetch faster. Pipelining overlaps them. Addressing modes
change how execute finds its operands. The control unit is the thing that
sequences them.

<!-- block: callout -->
**Five registers, and you will see them for fifteen weeks.**

| | |
|---|---|
| **PC** | Program Counter — *where next* |
| **IR** | Instruction Register — *what now* |
| **MAR** | Memory Address Register — *which cell* |
| **MBR** | Memory Buffer Register — *in transit* |
| **AC** | Accumulator — *the result* |

The strip along the top of this page is showing you exactly these. It has been
idling since Stage 00 on purpose. From **Stage 12** it runs live.

## Interrupts: why the loop is not quite that simple

A processor that only ever fetched and executed would have to *wait* for every
slow device — and an I/O device is thousands of times slower than the processor.
Waiting would waste almost all of it.

So the cycle gains a third step, checked after each execute: **has anything
asked for attention?** If so, the processor saves where it was, runs the
handler, and resumes.

That is the whole mechanism, and it is what makes a computer able to do more
than one thing. **Stage 07** does it properly; **Stage 08** shows how an
operating system builds on it.

<!-- block: prose -->
## Interconnection: what has to be able to reach what

Components are useless in isolation. The textbook enumerates exactly which
transfers the interconnection must support:

<!-- block: quote source="ch-03.md 3.3" -->
The interconnection structure must support the following types of transfers:

<!-- block: prose -->
Memory to processor, processor to memory, I/O to processor, processor to I/O —
and one more that is not a processor transfer at all:

<!-- block: quote source="ch-03.md 3.3" -->
For these two cases, an I/O module is allowed to exchange data directly with memory, without

<!-- block: prose -->
That last one is worth stopping on. An I/O module exchanging data with memory
**without going through the processor** is *direct memory access*, and it is the
single biggest reason a modern machine is not permanently stalled on disk. You
build it in **Stage 07**.

<!-- block: prose -->
## The bus, and why it eventually failed

<!-- block: quote source="ch-03.md 3.4" -->
A bus is a communication pathway connecting two or more devices. A key characteristic of a bus is that it is a shared transmission medium.

<!-- block: prose -->
Shared is the operative word, and the book states the consequence immediately:

<!-- block: quote source="ch-03.md 3.4" -->
If two devices transmit during the same time period, their signals will overlap and become garbled. Thus, only one device at a time can successfully transmit.

<!-- block: prose -->
A bus carries three kinds of line — **data**, **address**, and **control** — and
its width sets hard limits. A 32-line address bus can name 2³² locations and not
one more; a 64-line data bus moves 8 bytes per transfer.

**The bus is a beautiful idea that stopped working.** Every device attached adds
capacitance and lengthens the wires, so a wider, faster, more populated bus gets
*slower*. And only one device transmits at a time, so the whole machine
contends for one resource.

The answer was to stop sharing: **point-to-point interconnect**. QPI and PCI
Express are layered, packet-based links between pairs of devices, with multiple
transfers happening at once. The vocabulary shifts from *lines and cycles* to
*layers and packets* — physical, link, routing, protocol — which is closer to a
network than to a wire.

<!-- block: callout -->
**Notice what just happened to the abstraction.** A bus is a piece of physics
you can point at. PCIe is a protocol stack. As the hardware got faster, the
interconnect became a *communication system* — and the concepts you need to
reason about it are the ones from **Stage 18**, at the far end of this course.
